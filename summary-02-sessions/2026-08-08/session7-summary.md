## 關鍵決定（為什麼這樣做）

### 照片張數超出 skill 建議範圍時，優先保「秒數順暢」而非硬卡「總長上限」

skill 的 45–50 秒總長是針對 8–12 張照片設計的參考值，不是鐵律。17 張照片硬套公式會讓每張秒數低於
「3–4 秒最順」的下限，觀感會很趕。判斷「這條公式為什麼存在」（讓每張照片有足夠停留時間）比死守
「這個數字」更重要，所以放寬總長到 60 秒，保住 3 秒/張的節奏。

### 父親節影片加照片選擇「接續既有專案」而非「另開新專案重做」

11 張照片已經花時間調好模糊背景、片尾卡文字位置、光暈特效、配樂淡入淡出——這些都是需要來回調
座標/JSON 才能對準的工作。另開新專案等於全部重做一次；接續舊專案只需要「匯入 5 張 → 插入正確
位置 → 重算時長」，工作量小很多。判斷基準：新素材是「同一支影片的延伸」還是「全新影片」，前者
接續、後者才開新專案。

### 「套用到全部」出包後選擇「重新正確設定再套用一次」而非「用 JSON 手動寫入 canvas_blur」

json-schema-photo.md 原本就寫明「背景模糊不建議用 JSON 手動生成，用 UI 套用到全部最快最穩」。
出包後沒有回頭違反這條紀律去手刻 JSON（canvas material 的 id 生成、與 segment 的 extra_material_refs
關聯都有風險），而是回到 UI 用正確流程重做一次，JSON 只拿來「驗證」不拿來「新增」——事後看這個
判斷是對的，UI 重做一次只多花 2 分鐘，比排查手刻 JSON 出的怪 bug 划算。

## 關鍵技術筆記（本次新踩出來，skill 文件尚未記載）

### 1. CapCut 文字輸入框按 Enter 會「還原」而非「確認」，改用 Tab 或點擊他處

專案改名、音量/淡入淡出數值框皆遇到：Ctrl+A 全選 → Ctrl+V 貼上 → 按 Enter → 畫面顯示還原回原值。
改用 **Tab 鍵**或**點擊欄位以外的地方**（blur 觸發確認）就會正確保留新值。原因不明（可能是這版 CapCut
的 Enter 在特定輸入框被綁定成「取消編輯」而非「送出」），但這個規律在多個欄位（專案名稱、音量、
淡入、淡出）都重現，視為通用行為。

### 2. 點擊座標一律要「先裁切截圖檔案取得絕對座標」，不能直接用 Read 工具顯示的縮放座標估算

Read 工具顯示截圖時，若原圖超過約 2000px 寬會自動縮小顯示（例如 3840→2000，並註明「multiply by 1.92」）。
若直接用眼睛看縮小後的圖估座標、卻沒乘回縮放倍率就拿去 SetCursorPos，點擊會落在錯誤位置（甚至落到左
螢幕的 Claude Code 終端機視窗，而非右螢幕的 CapCut）。正確做法：用 PIL 對**已存檔的原始截圖檔案**做
`crop()`，crop 範圍座標與螢幕絕對座標是 1:1（因為 ImageGrab 抓的是原始解析度），估完加回 crop 的 offset
即為可直接 SetCursorPos 的絕對座標。這次因為沒守這條規則，浪費了多次無效點擊（尤其是找媒體庫左側子選單、
右鍵選單那幾次）。

### 3. CapCut 視窗只能用 `SW_MAXIMIZE`，不能對已最大化的視窗呼叫 `SW_RESTORE`

`SW_RESTORE` 在視窗**已經最大化**時會把它還原成一般大小的浮動視窗（而非保持最大化）；只有在視窗
**被最小化**時 `SW_RESTORE` 才是正確的「還原到之前狀態」。誤用會導致視窗突然變小、後續依賴全螢幕
座標基準的所有點擊全部失準。另外，對主視窗按 **ESC** 也可能意外觸發同樣的「取消全螢幕/還原」效果，
操作 CapCut 時應避免對主視窗按 ESC（若要清除卡住的拖曳滑鼠狀態，只需補一次 `mouse_event(MOUSEEVENTF_LEFTUP)`
即可，不需要按 ESC）。

### 4. 「背景→模糊」的強度縮圖（4 檔）不會馬上出現，需照特定順序操作才會捲動出來

正確順序（實測可重現）：① 選取照片片段 → ② 捲動到「背景」列（打勾狀態）→ ③ 點擊目前樣式（如「無」）
展開浮動選單（無/模糊/顏色/圖案/品牌背景）→ ④ 點「模糊」→ ⑤ **再點一次已選的「模糊」列關閉浮動選單**
→ ⑥ 這時候在面板上（游標在背景列附近，例如 y≈500）向下捲動，才會捲出 4 檔強度縮圖。如果跳過步驟 ⑤
直接捲動，捲動會卡在面板既有高度上限，看不到強度縮圖（我方誤以為選不到而放棄選強度，直接套用到全部，
結果套出的是「模糊」模式但強度未確認的狀態——不確定是否為本次出包的成因之一，保守起見以後都照這個順序做）。

### 5. 新增照片到既有時間軸：一律「拖到時間軸最尾端」再用 JSON 重新排序插入正確位置

嘗試把新照片直接拖到時間軸中段（片尾卡片之前的縫隙）風險高、精準度低。更穩的做法：
① 全選新照片，慢速拖曳到目前時間軸**最尾端**（片尾卡片之後，位置不重要，反正會被 JSON 重排）
② 關閉 CapCut，用 Python 對 `draft_content.json` 的 `tracks[0].segments` 陣列重新切片重組
（把新片段從陣列尾端搬到片尾片段之前），並重新計算所有 `target_timerange`/`source_timerange`
③ 這個做法把「UI 拖曳的不精準」和「JSON 的精確排序」分開處理，比硬要 UI 一次拖對位置可靠。
